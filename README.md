# 머더 타이머

친구들과 테이블 위에 휴대폰이나 태블릿 한 대를 두고 함께 보는 머더미스터리 진행용 단계 타이머입니다.
시나리오(단계 이름 + 시간 목록)를 만들어 두고, 게임 중에는 멀리서도 읽히는 큰 숫자로 남은 시간을 보여 줍니다.

- **시나리오 목록**: 서버에 저장되어 앱을 쓰는 모든 사용자에게 공유됩니다. 새로고침 버튼으로만 다시 불러옵니다(자동 폴링 없음).
- **게임 진행**: 시작할 때 시나리오 구성을 기기에 복사해 진행합니다. 진행 상황은 이 기기에만 저장되며 새로고침해도 이어집니다.
- **진행 결과**: 단계별 계획 시간과 실제 진행 시간(일시정지 제외, 초과 포함)을 비교합니다.

## 실행

Node.js 20.19 이상이 필요합니다.

```bash
npm install
npm run build      # 프론트엔드 빌드(dist/)
npm start          # http://localhost:8787 — 앱 화면과 API를 함께 제공
```

개발 중에는 `npm run dev`로 API 서버(8787)와 Vite 개발 서버(5173)를 함께 띄웁니다. Vite가 `/api` 요청을 API 서버로 넘깁니다.

같은 Wi‑Fi의 휴대폰에서 `http://<컴퓨터 IP>:8787`로 접속할 수 있습니다. 다만 **화면 꺼짐 방지(Wake Lock)와
오프라인 실행(서비스 워커)은 HTTPS 또는 localhost에서만** 동작하므로, 실제로 쓸 때는 HTTPS 주소로 배포하는 것을 권장합니다.

### 서버 설정(환경 변수)

| 이름                   | 기본값            | 설명                                                                       |
| ---------------------- | ----------------- | -------------------------------------------------------------------------- |
| `PORT`                 | `8787`            | 서버 포트                                                                  |
| `HOST`                 | `0.0.0.0`         | 바인딩 주소                                                                |
| `DATA_DIR`             | `./data`          | 시나리오 저장 폴더(`scenarios.json`). **재시작·재배포 후에도 남는 디스크**여야 합니다. |
| `STATIC_DIR`           | `./dist`          | 빌드된 앱 화면 폴더                                                        |
| `TRASH_RETENTION_DAYS` | `30`              | 휴지통 보관 기간. 지나면 영구 삭제                                         |
| `CORS_ORIGIN`          | (없음)            | 앱 화면을 다른 주소에 올릴 때 허용할 출처. 예: `https://example.github.io` |

앱 화면과 서버를 다른 주소에 올릴 때는 빌드할 때 `VITE_API_BASE=https://서버주소 npm run build`로 API 주소를 지정합니다.
화면은 상대 경로로 빌드되고 해시 라우팅(`#/...`)을 쓰므로 GitHub Pages 같은 정적 호스팅의 하위 경로에도 올릴 수 있습니다.

> 이 서버에는 로그인이 없습니다. 주소를 아는 사람은 누구나 시나리오를 만들고 고치고 지울 수 있습니다(휴지통에서 30일간 복원 가능).
> 공개 인터넷에 올린다면 접근 제한(예: 리버스 프록시의 기본 인증)을 함께 두는 것을 권장합니다.

## 앱 이름 바꾸기

`src/config.ts`의 `name`, `shortName`만 고치면 됩니다. 화면 상단, 브라우저 탭 제목, 홈 화면 아이콘 이름(manifest)에 모두 반영됩니다.
아이콘 이미지는 `public/icons/*.svg`를 고친 뒤 `npm run icons`로 PNG를 다시 만듭니다.

## 화면

| 화면                  | 주소               | 내용                                                                                   |
| --------------------- | ------------------ | -------------------------------------------------------------------------------------- |
| 시나리오 목록         | `#/`               | 진행 중인 게임 이어가기, 새 시나리오, 저장된 시나리오(열기·더보기), 템플릿으로 만들기 |
| 열기(시트)            | `#/scenario/:id`   | 단계 구성과 시간 확인 → 편집 또는 게임 시작                                           |
| 시나리오 편집         | `#/new`, `#/edit/:id` | 이름 → 단계 목록 → 단계 추가 → 빠른 입력 → 총 계획 시간·저장                         |
| 게임 진행             | `#/play`           | 큰 남은 시간, 상태·진행 바, 다음 단계·전체 남은 시간, 조작 버튼                       |
| 진행 결과             | `#/result`         | 계획/실제/차이 요약, 단계별 비교                                                      |
| 휴지통(보조 화면)     | `#/trash`          | 복원, 영구 삭제                                                                        |
| 설정(모달)            | 목록 상단 버튼     | 알림음, 진동, 화면 꺼짐 방지(이 기기에만 저장)                                        |

## 진행 규칙

- 단계 시간이 0이 되면 알림(소리·진동·한 번의 부드러운 강조) 후 초과 시간을 `+01:23` 형식으로 계속 셉니다. 마지막 단계도 같으며, 이때 주요 버튼이 ‘게임 마치기’로 바뀝니다.
- 남은 시간 1분 이하는 앰버색 + ‘진행 중 · 1분 이하’, 시간 초과는 빨간색 + ‘시간 초과’로 글자와 아이콘을 함께 표시합니다.
- **실제 진행 시간** = 일시정지 시간을 뺀 실행 시간(초과 시간 포함). **±1분**은 현재 단계의 배정 시간만 바꾸며 실제 진행 시간은 바꾸지 않습니다. 남은 시간이 없으면 −1분은 누를 수 없습니다.
- 결과의 계획 시간은 게임 시작 시점의 원래 계획입니다.
- **이전 단계**로 돌아가면 그 단계를 원래 계획 시간으로 새로 시작하고, 실제 시간은 그 단계에서 실행한 시간을 누적합니다.
- **다음 단계·이전 단계·게임 마치기(시간이 남았을 때)·게임 종료**는 확인 후 실행합니다. 시간 초과 상태의 ‘다음 단계 시작’은 바로 실행하되, 버튼 역할이 바뀐 직후 0.8초 동안은 누름을 무시해 잘못 누르는 것을 막습니다.
- **전체 남은 시간** = 현재 단계 남은 시간(초과 중이면 0) + 이후 단계 계획 시간의 합. 초과 중에는 ‘초과 시간 제외’를 함께 표시합니다.
- 다른 기기에서 서버의 시나리오를 고쳐도 진행 중인 게임의 이름·순서·시간은 바뀌지 않습니다.
- 같은 시나리오를 동시에 고치면 저장할 때 충돌을 알려 주고(버전 `rev` 비교), 덮어쓸지 고르게 합니다.

### 빠른 입력 형식

한 줄에 한 단계, 줄 끝에 시간을 적습니다. 빈 줄과 `#`으로 시작하는 줄은 건너뜁니다.

```
사건 소개 5          ← 숫자만 쓰면 분
1차 조사 20분
1차 토론 15:30       ← 분:초
긴 조사 1:30:00      ← 시:분:초
해설 7분 30초
```

## 구조

```
server/            의존성 없는 Node 서버(정적 파일 + JSON API, 파일 저장)
shared/limits.json 서버·화면이 함께 쓰는 입력 제한(이름 길이, 단계 수, 최대 시간)
src/config.ts      앱 이름(한 곳에서 변경)
src/styles/        디자인 토큰(tokens.css)과 기본 스타일
src/components/    공통 컴포넌트: Button·IconButton, TextField, Modal·ConfirmDialog, Menu, InlineAlert, Toast, Switch, EmptyState, Icon …
src/screens/       화면(목록, 열기 시트, 편집, 진행, 결과, 휴지통, 설정)
src/game/          진행 계산(engine.ts, 순수 함수)과 기기 저장
src/data/          API 클라이언트, 목록 캐시 저장소, 편집 초안 검사, 템플릿
```

색·글자 크기·간격·모서리·버튼 높이는 모두 `src/styles/tokens.css`의 토큰으로 관리합니다.

### API

| 메서드·경로                            | 설명                                           |
| -------------------------------------- | ---------------------------------------------- |
| `GET /api/scenarios`                   | 목록(휴지통 제외), 최근 수정순                  |
| `POST /api/scenarios`                  | 만들기 `{ name, stages: [{ id?, name, durationSec }] }` |
| `PUT /api/scenarios/:id`               | 고치기 `{ name, stages, rev }` — `rev`가 다르면 409 `conflict` |
| `PATCH /api/scenarios/:id`             | 이름 바꾸기 `{ name }`                          |
| `POST /api/scenarios/:id/duplicate`    | 복제(‘이름 (복사본)’)                           |
| `DELETE /api/scenarios/:id`            | 휴지통으로 이동                                 |
| `GET /api/trash`                       | 휴지통 목록                                     |
| `POST /api/trash/:id/restore`          | 복원                                            |
| `DELETE /api/trash/:id`                | 영구 삭제                                       |

## 테스트

```bash
npm test                 # 단위 테스트(vitest) + 서버 API 테스트(node:test)
npm run test:e2e         # 빌드 후 Playwright E2E(모바일 Chromium)
npm run qa:screens       # 화면 점검: 여러 화면 크기·상태 스크린샷 + 가로 넘침/터치 영역/겹침 자동 검사
```

`qa:screens`는 **실행 중인 서버의 데이터를 지우고** 점검용 시나리오로 채웁니다. 점검 전용 데이터 폴더로 띄운 서버에서만 실행하세요.

```bash
DATA_DIR=/tmp/mt-qa npm start &
npm run qa:screens       # 결과: e2e/screenshots/*.png, report.json
```

## UI 점검 결과

Playwright(Chromium) 기기 흉내로 아래 크기에서 화면을 캡처해 확인했습니다. 화면당 가로 넘침, 44px 미만 터치 영역,
52px 미만 주요 버튼, 진행 화면 요소 겹침, 버튼 글자 잘림을 자동 검사했고 모두 통과했습니다.

- 크기: 360×740, 390×844, 375×667, 태블릿 세로 768×1024, 태블릿 가로 1024×768, 휴대폰 가로 844×390·640×360
- 상태: 기본·일시정지·1분 이하·시간 초과·마지막 단계 초과, 긴 시나리오 이름·긴 단계 이름, 단계 30개, 1시간 이상 단계
- 빈 상태·예외: 첫 사용, 불러오는 중, 오프라인(저장된 목록 표시), 오프라인(저장된 목록 없음), 입력 오류, 저장 실패, 저장 전 나가기, 휴지통 비어 있음

진행 화면의 남은 시간 숫자 크기(측정값): 360px 폭 113px(`14:32`)·93px(`+01:23`)·85px(`1:29:30`), 태블릿 세로 249px, 태블릿 가로 190px, 휴대폰 가로 154px.

### 직접 확인하지 못한 항목

이 환경에서는 실제 기기와 브라우저를 쓸 수 없어 아래는 **확인하지 못했습니다.**

- 실제 iPhone Safari / Android Chrome / iPad에서의 표시와 동작(점검은 Linux Chromium의 기기 흉내로만 했고, 글꼴도 Noto Sans CJK로 렌더링됨)
- 알림음 재생, 진동, 화면 꺼짐 방지(Wake Lock), 전체화면 전환의 실제 동작
  - iPhone Safari는 전체화면 API와 진동을 지원하지 않아 전체화면 버튼이 보이지 않고 진동 설정이 꺼진 상태로 표시되도록 만들었지만, 실기기 확인은 못 했습니다.
- 실제 화면 키보드가 올라왔을 때 저장 영역이 입력칸을 가리지 않는지(키보드가 열리면 하단 고정을 푸는 방식으로 구현)
- 터치 화면에서 손잡이 끌기와 페이지 스크롤이 겹치지 않는지(마우스 끌기와 키보드 이동은 E2E로 확인)
- 노치·홈 표시줄 안전 여백(safe-area)이 실제로 적용된 모습
- 홈 화면에 추가한 앱(PWA)과 서비스 워커의 오프라인 실행
- 백그라운드에 오래 있다가 돌아왔을 때의 알림 동작(시간 계산은 시각 차이로 하므로 맞게 이어지도록 구현)
